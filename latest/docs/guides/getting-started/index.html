      Getting Started#

      Install the SDK and make your first API call against Cribl.Cloud or an on-prem Leader. One Cribl client covers the control plane and the Cribl.Cloud platform API, with authentication and token refresh handled for you.

      Install#

      Requires Python 3.14 or later.

      uv add cribl-python-sdk
      pip install cribl-python-sdk
      poetry add cribl-python-sdk

      Quickstart#

      A complete script: check server health, list Worker Groups, then list Sources and Pipelines in one group. Replace the placeholders with your own values.

      from cribl_python_sdk import Cribl, Security

with Cribl(
    server_url="https://main-your-org.cribl.cloud",  # your Workspace URL
    security=Security(client_id="your-client-id", client_secret="your-client-secret"),
) as cribl:
    health = cribl.health.get()
    print(f"Server health: {health.data.status}")

    groups = cribl.groups.list()
    print(f"Found {groups.data.count} Worker Group(s)")

    # Control-plane calls scoped to one Worker Group
    with cribl.in_context(group_id="default") as wg:
        print(f"Found {wg.sources.list().data.count} Source(s)")
        print(f"Found {wg.pipelines.list().data.count} Pipeline(s)")

    # Cribl.Cloud platform API: same client, same credentials
    workspaces = cribl.cloud.workspaces.list(organization_id="your-org")
    print(f"Found {len(workspaces.data.items)} Workspace(s)")

      Async#

      Every method has an _async twin. Use async with inside a coroutine and run it with asyncio.run():

      import asyncio

from cribl_python_sdk import Cribl, Security


async def main() -> None:
    async with Cribl(
        server_url="http://localhost:9000",
        security=Security(username="admin", password="admin"),
    ) as cribl:
        health = await cribl.health.get_async()
        print(f"Server health: {health.data.status}")

        groups = await cribl.groups.list_async()
        print(f"Found {groups.data.count} Worker Group(s)")


asyncio.run(main())

      See examples/ for more usage patterns.

      Reference for the methods used above: health.get, groups.list, sources.list, pipelines.list, cloud.workspaces.list, in_context.

      Authentication#

      The SDK handles token acquisition and refresh automatically: pass credentials once in Security(...) and the client manages the rest. Every snippet below plugs into Cribl(server_url=..., security=security) as in the Quickstart.

      DeploymentSecurity(...)Authenticates
      On-premusername=, password=Control plane
      Cribl.Cloudclient_id=, client_secret=Control plane and cribl.cloud.*
      Anybearer_auth=Whatever the token is valid for

      On-Prem (username/password)#

      The client calls POST /auth/login internally, stores the JWT, and refreshes it before expiry.

      from cribl_python_sdk import Security

security = Security(username="admin", password="admin")

      Cloud — Control Plane (OAuth2)#

      OAuth2 client credentials flow. The SDK fetches and refreshes the access token automatically.

      from cribl_python_sdk import Security

security = Security(client_id="your-client-id", client_secret="your-client-secret")

      Cloud — Management Plane (cribl.cloud.*)#

      Same client, same credentials. Management plane operations live under the cribl.cloud.* namespace and route to the gateway (https://gateway.cribl.cloud by default), while control-plane calls go to server_url.

      Pre-existing Bearer Token#

      If you already have a token (e.g. from an external auth flow), pass it directly — no auto-login or refresh:

      from cribl_python_sdk import Security

security = Security(bearer_auth="your-token")

      How the client is organized#

      APIWhere it runsSDK
      Control planeYour Cribl leader (server_url) — on-prem or Cribl.Cloudclient.pipelines, client.sources, …
      Cribl.Cloud platformCribl.Cloud gateway (https://gateway.cribl.cloud)client.cloud.* — workspaces, API credentials, billing

      On Cribl.Cloud, the same Security(client_id=..., client_secret=...) authenticates both. On-prem username/password authenticates the control plane only.

      Scoped Client#

      Instead of manually constructing group/node URLs, use in_context(). Control-plane calls route to /api/v1/m/{group_id} automatically; cribl.cloud.* is unchanged (still the gateway).

      from cribl_python_sdk import Cribl, Security

with Cribl(
    server_url="http://localhost:9000",
    security=Security(username="admin", password="admin"),
) as cribl, cribl.in_context(group_id="my_fleet") as wg:
    sources = wg.sources.list()
    destinations = wg.destinations.list()
    pipelines = wg.pipelines.list()

      Creating Resources#

      Pipelines take explicit keyword arguments:

      from cribl_python_sdk import Cribl, Security

with Cribl(
    server_url="http://localhost:9000",
    security=Security(username="admin", password="admin"),
) as cribl, cribl.in_context(group_id="default") as wg:
    wg.pipelines.create(id="my_pipe", conf={"functions": []})

      Sources, Destinations and Collectors accept either a typed model or a plain dict. Pick one:

      from cribl_python_sdk import Cribl, Security
from cribl_python_sdk.models.inputs import InputSyslog

with Cribl(
    server_url="http://localhost:9000",
    security=Security(username="admin", password="admin"),
) as cribl, cribl.in_context(group_id="default") as wg:
    wg.sources.create(InputSyslog(id="syslog_typed", host="0.0.0.0", udpPort=514))

      Environment Variables#

      VariableDescription
      CRIBL_SERVER_URLOn-prem server origin (e.g. http://localhost:9000)
      CRIBL_USERNAMEOn-prem login username
      CRIBL_PASSWORDOn-prem login password
      CRIBL_CLOUD_URLCribl.Cloud workspace origin for the control plane (e.g. https://main-your-org.cribl.cloud)
      CRIBL_CLOUD_GATEWAY_URLPlatform/mgmt gateway override (default: https://gateway.cribl.cloud)
      CRIBL_CLIENT_IDOAuth2 client ID (Cloud control plane + cribl.cloud.*)
      CRIBL_CLIENT_SECRETOAuth2 client secret (Cloud control plane + cribl.cloud.*)
      CRIBL_AUDIENCEOAuth2 audience (default: https://api.cribl.cloud)
      CRIBL_TOKEN_URLOAuth2 token endpoint (default: https://login.cribl.cloud/oauth/token)
      CRIBL_WORKER_GROUP_IDTarget worker group ID
      CRIBL_ORGANIZATION_IDCribl.Cloud organization id for cribl.cloud.* examples
      CRIBL_SDK_DEBUGSet to true to enable debug logging (zero-code activation)

      Advanced Usage#

      Shell and script usage with uv#

      Use in a Python shell:

      uvx --from cribl-python-sdk python

      Standalone script without a project:

      #!/usr/bin/env -S uv run --script
# /// script
# requires-python = ">=3.14"
# dependencies = [
#     "cribl-python-sdk",
# ]
# ///

from cribl_python_sdk import Cribl, Security

cribl = Cribl(
    server_url="http://localhost:9000",
    security=Security(username="admin", password="admin"),
)
print(cribl.health.get().data.status)

      Run with uv run script.py.
