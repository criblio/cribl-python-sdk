      Operations#

      create#

      client.versioning.commits.create(...)

      Create a new commit for pending changes to the Cribl configuration.

      Any merge conflicts indicated in the response must be resolved using Git. To commit only a subset of configuration changes, specify the files to include in the commit in the files array.

      Example Usage#

      # Example request body for committing all pending changes to the Cribl configuration.
client.versioning.commits.create(
    message="Updated pipeline configuration for syslog parsing",
)

      Parameters#

      ParameterTypeRequiredDefaultDescription
      messagestrYes—Commit message to use for the new Git commit
      effectivebool | NoneNo—If true, apply the commit to the group’s effective configuration. Requires a group context
      fileslist[str] | NoneNo—Array of file paths to include in the commit, relative to the configuration root. If omitted, all pending changes are committed

      Response#

      SDKResponse

      (200) PaginatedResponse containing GitCommitSummary objects.

      response = client.versioning.commits.create(...)
for item in response.data.items:
    print(item)

      Errors#

      This operation may raise the following SDK exceptions.

      ErrorStatus CodeDescription
      ValidationError400When effective: true is provided without a group context.
      AuthenticationError401Authentication failed (missing or invalid credentials or Bearer token).
      ServerError500Unexpected server error.

      Commit changes in specific files

      # Example request body for committing a subset of configuration changes to specific files.
client.versioning.commits.create(
    message="Update Route and Pipeline for HTTP Sources",
    effective=True,
    files=[
        "groups/default/local/cribl/pipelines/http_input/conf.yml",
        "groups/default/local/cribl/routes.yml",
    ],
)

{"count": 1, "items": [...]}

      diff#

      client.versioning.commits.diff(...)

      Get the diff for a commit.

      Default is the latest commit (HEAD).

      Example Usage#

      response = client.versioning.commits.diff()

      Parameters#

      ParameterTypeRequiredDefaultDescription
      commitstr | NoneNo—The Git commit hash to get the diff for
      filenamestr | NoneNo—The relative path of the file to get the diff for
      diffLineLimitint | NoneNo—Number of lines of the diff to return. Default is 1000. Set to 0 to return the full diff, regardless of the number of lines

      Response#

      SDKResponse

      (200) PaginatedResponse containing the requested GitDiffResult.

for item in response.data.items:

      push#

      client.versioning.commits.push(...)

      Push local commits to the remote repository.

      Push all local commits from the local repository to the remote repository. Requires at least one local commit that has not been pushed. Returns an error if the remote repository cannot be reached or the push is rejected.

      Example Usage#

      revert#

      client.versioning.commits.revert(...)

      Revert a commit in the local repository.

      Revert a commit in the local repository by creating a new commit that undoes the changes introduced by the specified commit. Use the force field to proceed even when the working directory is not clean.

      Example Usage#

      # Example request body for reverting a specific commit.
client.versioning.commits.revert(
    commit="a1b2c3d4e5f6",
)

      Parameters#

      ParameterTypeRequiredDefaultDescription
      commitstrYes—SHA-1 hash of the commit to revert
      forcebool | NoneNo—If true, force the revert even when the working directory is not clean. Otherwise, false
      messagestr | NoneNo—Custom message to use for the revert commit. If omitted, a default message is generated

      Response#

      SDKResponse

      (200) PaginatedResponse containing GitRevertResult objects.

      response = client.versioning.commits.revert(...)
for item in response.data.items:
    print(item)

      Errors#

      This operation may raise the following SDK exceptions.

      ErrorStatus CodeDescription
      AuthenticationError401Authentication failed (missing or invalid credentials or Bearer token).
      ServerError500Unexpected server error.

      Force revert a commit with a custom message

      # Example request body for force reverting a specific commit with a custom revert message.
client.versioning.commits.revert(
    commit="a1b2c3d4e5f6",
    message="Revert commit due to misconfiguration in Pipeline settings",
    force=True,

      undo#

      client.versioning.commits.undo(...)

      Discard uncommitted (staged) changes.

      Discard all uncommitted (staged) configuration changes, resetting the working directory to the last committed state. Use only if you are certain that you do not need to preserve your local changes. When applied globally (no group), triggers a Cribl restart to reload the reverted configuration. Returns false if the working directory is already clean.

      Example Usage#

      response = client.versioning.commits.undo()

      Response#

      SDKResponse

      (200) PaginatedResponse containing bool objects.

      response = client.versioning.commits.undo(...)
for item in response.data.items:
    print(item)

      Errors#

      This operation may raise the following SDK exceptions.

      ErrorStatus CodeDescription
      AuthenticationError401Authentication failed (missing or invalid credentials or Bearer token).
      ServerError500Unexpected server error.

      Undo result — Response

      # Example response for discarding uncommitted changes.
{"count": 1, "items": [True]}
