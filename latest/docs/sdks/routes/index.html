      • Operations

      Manage data routing rules connecting sources to pipelines and destinations.

      client.routes

      Overview#

      MethodDescription
      appendAdd a Route to the end of the Routing table.
      getGet a Routing table.
      listList all Routes.
      updateUpdate a Routing table.

      Operations#

      append#

      client.routes.append(...)
await client.routes.append_async(...)

      Add a Route to the end of the Routing table.

      Add a Route to the end of the specified Routing table.

      Example Usage#

      # Example request body for appending a single Route to the end of the default Routing table ( id: default ).
client.routes.append(
    [
        {
            "id": "route-new",
            "name": "new-route",
            "pipeline": "main",
            "filter": "source == \"new.log\"",
            "description": "Route new logs to main pipeline",
            "final": True,
        },
    ],
)

      Parameters#

      ParameterTypeRequiredDescription
      idstrYesThe id of the Routing table to add the Route to. The supported value is default
      routeslist[RouteConfParam]YesRoute configurations to append to the Routing table
      packstr | NoneNoPack ID. If provided, scopes the operation to the specified Pack

      Response#

      SDKResponse

      (200) PaginatedResponse containing Routes objects.

      response = client.routes.append(...)
for item in response.data.items:
    print(item)

      Errors#

      This operation may raise the following SDK exceptions.

      ErrorStatus CodeDescription
      ValidationError400Failed validation or malformed input. The request body must be an array of Route configurations.
      AuthenticationError401Authentication failed (missing or invalid credentials or Bearer token).
      NotFoundError404Routing table not found. The specified id does not match any stored Routing table.
      ServerError500Unexpected server error.

      Append multiple Routes to the Routing table

            "description": "Route security logs",

)

      Append a Route with dynamic Destination expression

      # Example request body for appending a Route to the end of the default Routing table ( id: default ) that uses a JavaScript expression to dynamically determine the Destination at Route startup.
client.routes.append(
    [
        {
            "id": "route-dynamic-append",
            "name": "dynamic-append",
            "pipeline": "main",
            "enableOutputExpression": True,
            "outputExpression": "`myDest_${C.logStreamEnv}`",
            "filter": "source == \"dynamic.log\"",
            "description": "Route with dynamic Destination based on environment",
            "final": True,
        },
    ],
)

      Append a Route omitting optional id and final fields

            "description": "Route with server-generated id and default final value",

      update#

      client.routes.update(...)
await client.routes.update_async(...)

      Update a Routing table.

      Update the specified Routing table. Provide a complete representation of the Routing table that you want to update in the request body. This endpoint does not support partial updates. Cribl removes any omitted fields when updating the Routing table. Confirm that the configuration in your request body is correct before sending the request. If the configuration is incorrect, the updated Routing table might not function as expected. Cribl also removes any omitted Routes when updating the Routing table.

      Example Usage#

      # Example request body for updating the default Routes table ( id: default ) with a simple Route that filters access.log events and sends them to the main Pipeline. The request body must include a complete representation of the Routing table that you want to update. This endpoint does not support partial updates.
client.routes.update(
    id="default",
    routes=[
        {
            "id": "default",
            "name": "my-route",
            "pipeline": "main",
            "filter": "source == \"access.log\"",
            "description": "Route access logs to main Pipeline",
            "final": True,
        },
    ],
)

      Parameters#

      ParameterTypeRequiredDescription
      idstrYesThe id of the Routing table to update. The supported value is default
      routeslist[RouteConfParam]YesArray of Route configurations that define how events are processed and routed
      commentslist[RouteCommentParam] | NoneNoArray of user-provided comments that describe or annotate Routes
      groupsdict[str, RouteGroupParam] | NoneNoInformation about the Route Groups that the Route is associated with
      packstr | NoneNoPack ID. If provided, scopes the operation to the specified Pack

      Response#

      SDKResponse

      (200) PaginatedResponse containing the updated Routes.

      response = client.routes.update(...)
for item in response.data.items:
    print(item)
